## 1. Supabase

**Purpose**: All-in-one backend — database, authentication, file storage, and real-time subscriptions.

### Authentication
- **Method**: Email/password via Supabase Auth
- **SDK**: `@supabase/supabase-js` 2.45.0 + `@supabase/ssr` 0.5.0
- **Flow**: User signs in → Supabase issues a JWT → cookie-based session managed by `@supabase/ssr`
- **Session refresh**: Middleware on every request calls `supabase.auth.getUser()` to refresh the session cookie
- **Auto-provisioning**: Database trigger `handle_new_user()` creates a `public.users` profile when a new `auth.users` record is created

### Database (PostgreSQL via PostgREST)
- **Access pattern**: Server components and server actions create a Supabase client and use PostgREST syntax (`.from().select().eq()`)
- **Two client types**:
  - Standard client (`createClient()` in `src/lib/supabase/server.ts`): Uses anon key + user cookies, RLS enforced
  - Admin client (`createAdminClient()` in `src/lib/supabase/server.ts`): Uses service role key, bypasses RLS — only used for admin operations (creating auth users, managing teams)
- **Browser client** (`createBrowserClient()` in `src/lib/supabase/client.ts`): Used for real-time subscriptions in client components
- **Error handling**: Inline — check `error` return from each query. No global error interceptor.
- **Rate limits**: Standard Supabase tier limits apply (varies by plan)

### File Storage
- **Bucket**: `deal-documents` (private)
- **Path pattern**: `deals/{dealId}/{documentType}/{timestamp}.{ext}`
- **Operations**: Upload, download, signed URL (1-hour expiry), delete, replace
- **File constraints**: PDF, JPG, PNG, DOC, DOCX. Max 10MB.
- **SDK methods used**:
  ```
  storage.from('deal-documents').upload(path, file, { cacheControl, contentType, upsert })
  storage.from('deal-documents').download(path)
  storage.from('deal-documents').createSignedUrl(path, 3600)
  storage.from('deal-documents').remove([path])
  ```

### Realtime
- **Purpose**: Live deal updates and toast notifications
- **SDK methods used**:
  ```
  supabase.channel(channelName).on('postgres_changes', { event, schema, table, filter }, callback).subscribe()
  ```
- **Channels**: One per deal subscription (deals table changes), one for notifications table
- **Used in**: `src/hooks/useRealtimeDeals.ts`, `src/hooks/useNotifications.ts`
- **Cleanup**: Channels are removed on component unmount

### Setup Requirements
- Supabase project with PostgreSQL database
- `deal-documents` storage bucket (private)
- All 11 migrations applied in order
- Environment variables: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`

## 2. Google Fonts

**Purpose**: Roboto font family loading

- **Usage**: `next/font/google` import in `src/app/layout.tsx`
- **Font**: Roboto (weights: 300, 400, 500, 700)
- **Method**: Next.js automatically downloads and self-hosts the font at build time. No runtime requests to Google.
- **No API key needed**
